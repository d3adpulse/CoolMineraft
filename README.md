# VoxelCraft — воксельный прототип на Godot 4.5 (.NET / C#)

Полный прототип по этапам 0–9: блоки-данные, чанки 16×128×16, генерация рельефа
на `FastNoiseLite`, меш с отсечением граней, загрузка/выгрузка чанков вокруг игрока,
многопоточная генерация, установка/разрушение блоков, сохранение только изменений.

Проект **компилируется без ошибок и предупреждений** (`dotnet build`).

---

## 1. Что нужно установить

| Что | Версия | Где |
|---|---|---|
| **Godot .NET (Mono)** | **4.5.x .NET** (проверено на 4.5.1) | <https://godotengine.org/download/windows/> → вариант **.NET**, не обычный |
| **.NET SDK** | 8.0 или новее | <https://dotnet.microsoft.com/download> |

> Важно: обычная (не .NET) сборка Godot не умеет C#. В названии файла должно быть
> `Godot_v4.5.1-stable_mono_win64.exe` или `Godot_v4.5.1-stable_dotnet_win64.exe`.

Если поставите Godot 4.6/4.7 — движок предложит обновить проект. После этого
поменяйте версию SDK в `VoxelCraft.csproj`:

```xml
<Project Sdk="Godot.NET.Sdk/4.5.1">
```

на версию вашего движка (например `4.6.0`) и нажмите **Build**.

## 2. Запуск

1. Godot → **Import** → выбрать `project.godot` из этой папки.
2. Дождаться импорта (появится `.godot/`), нажать **Build** (иконка молотка) — соберётся C#.
3. **F5**.

При первом запуске в консоли будет:
- `[SaveSystem] Сохранения нет. Новый seed: ...`
- ASCII-карта высот 3×3 чанка (этап 3) — по ней сразу видно, что рельеф связный, а не шум.

## 3. Управление

| Клавиша | Действие |
|---|---|
| WASD | движение |
| Space | вверх (полёт) / прыжок (ходьба) |
| Shift | вниз (полёт) |
| Ctrl | ускорение |
| **F** | переключить полёт / ходьбу |
| ЛКМ | сломать блок |
| ПКМ | поставить блок |
| 1…5, колесо мыши | выбор блока |
| Esc | освободить курсор (клик — вернуть) |

Игрок появляется в режиме полёта — так он не проваливается, пока первые чанки
генерируются в фоне. Нажмите **F**, чтобы начать ходить.

## 5. Как это работает (по этапам)

### Этап 1. Блоки — данные
`BlockId : byte`, `BlockDef : Resource`. Таблица — массив на 256 элементов,
индексация по `(byte)id`, т.е. O(1). Никаких узлов на блок.

### Этап 2. Чанк
`Chunk` = `BlockId[32768]` (плоский массив, 32 КБ), адресация
`Index(x,y,z) = x + 16*(z + 16*y)`.
`Chunk.GetBlock(x,y,z)` умеет выходить за границы: снизу — камень, сверху — воздух,
по X/Z — спрашивает `ChunkManager`.

### Этап 3. Рельеф
`WorldGenerator.FillChunk` работает только с массивом, поэтому вызывается из потока.
Высота = базовая + крупный шум + мелкая деталь, пляжи у уровня моря, пещеры 3D-шумом.
`PrintHeightMap()` печатает ASCII-карту 48×48.

### Этап 4. Меш с face culling
Для каждого блока проверяются 6 соседей. Грань добавляется, только если сосед
прозрачный (и не такой же прозрачный блок). Правило:

```
сосед == Air            → рисуем
сосед == self           → не рисуем (вода-вода)
сосед opaque            → не рисуем
иначе                   → рисуем, только если сам блок opaque
```

Порядок вершин грани — TL → TR → BR → BL, индексы `0,1,2 / 0,2,3`
(Godot считает лицевой стороной CW). UV берутся из атласа с отступом в полтекселя,
чтобы не «подтекали» соседние тайлы. Плюс лёгкое затенение по направлению грани
через вершинные цвета.

Проверка критерия: HUD показывает «Треугольников». Полный куб без culling — это
196 608 граней на чанк; в реальном рельефе видно на порядок меньше.

### Этап 5. ChunkManager
Чанки в радиусе `ViewDistanceInChunks` (5 → примерно 81 чанк) ставятся в очередь
по возрастанию расстояния, выгружаются с запасом +2. За кадр применяется
`MaxChunksPerFrame` (2) результатов — без фризов.

### Этап 6. Потоки
- **Фоновый поток** (`Task.Run`): `FillChunk` + применение сохранённых модификаций +
  `ChunkMeshBuilder.Build` → обычные массивы `Vector3[]/int[]`.
- **Главный поток**: `ArrayMesh`, `MeshInstance3D`, `CollisionShape3D` (trimesh), `AddChild`.

Соседние чанки копируются на главном потоке **до** старта задания, поэтому
фоновый поток никогда не читает массив, который в этот момент меняет игрок.
`SceneTree` из фона не трогается вообще.

### Этап 7. Взаимодействие
`PhysicsRayQueryParameters3D` из камеры на `Reach = 8`. Точка попадания сдвигается
на `-normal * 0.5`, чтобы получить целочисленные координаты блока. При установке
блока проверяется, что место свободно и не пересекается с игроком.
Если изменённый блок на границе чанка — перестраиваются оба чанка.

### Этап 8. Ассеты
Атлас `block_atlas.png` — 4×4 тайла по 16×16, собран из свободных текстур
(см. `CREDITS.md`). UV считаются кодом, поэтому отдельная модель куба не нужна
(в самом задании это описано как «альтернатива для блоков»).
В `Assets/Models` лежат CC0-модели Kenney (`character-a.glb`, `character-m.glb`) —
их можно перетащить в сцену, чтобы проверить импорт glTF 2.0.
Материал: `StandardMaterial3D`, `TextureFilter = Nearest`,
`VertexColorUseAsAlbedo = true`, `CullMode = Back`.

В `project.godot` стоит `[importer_defaults]` с `detect_3d/compress_to = 0`,
иначе Godot при использовании текстуры в 3D пересоберёт её в VRAM-сжатие
и пиксель-арт «поплывёт».

### Этап 9. Сохранение
`user://world_save.json`:

```json
{ "Seed": 123456, "Blocks": [[10, 64, 3, 0], ...] }
```

При генерации чанка модификации применяются поверх шума. Автосейв раз в 3 секунды
после изменений, плюс при выходе и по F5.

## 6. Чек-лист оптимизации

| Проверка | Где смотреть | Что крутить |
|---|---|---|
| Face culling работает | HUD → «Треугольников» | `ChunkMeshBuilder.ShouldRenderFace` |
| Нет фризов при генерации | HUD → FPS, Profiler | `MaxChunksPerFrame`, `MaxConcurrentJobs` |
| Чанки выгружаются | HUD → «Чанков загружено» | `ViewDistanceInChunks` |
| Меш не перестраивается каждый кадр | точка входа `RebuildChunk` | перестройка только по изменению блока |
| Текстуры не размыты | материал + `importer_defaults` | `TextureFilterEnum.Nearest`, `compress_to = 0` |
| Коллизия не «плывёт» | ходьба по блокам | коллизия из финального меша, `GenerateCollision` |

## 7. Ограничения прототипа (осознанные)

- **Вода непрозрачная** (рисуется тем же материалом). Данные и правила culling
  уже готовы под прозрачность — нужен второй материал/проход.
- **Нет greedy meshing**: по одному кваду на грань, зато код простой и понятный.
- **Нет деревьев**: они требуют записи в соседние чанки, это отдельная задача.
- **Нет освещения/AO**: только направленное солнце + затенение по нормалям.
- **Соседние чанки не перестраиваются при появлении нового чанка** — на границах
  остаются невидимые «внутренние» грани (трафик, не артефакт). При изменении блока
  игроком границы перестраиваются корректно.
- Коллизия — `trimesh` на чанк; для больших миров стоит перейти на
  `ConcavePolygonShape3D` с меньшим числом треугольников или на greedy meshing.

## 9. Частые проблемы

| Симптом | Причина / решение |
|---|---|
| `Godot.NET.Sdk/4.5.1 not found` | Установлена не .NET-версия Godot или другой SDK. Проверьте версию в `VoxelCraft.csproj` |
| Проект открылся, но скриптов нет | Не нажали **Build**; в консоли будет `CS...`. Соберите проект |
| Всё розовое | Не импортировался `block_atlas.png` — проверьте путь `res://Assets/Textures/block_atlas.png` |
| Игрок висит в воздухе | Это режим полёта. Нажмите **F** |
| Пустой мир | Подождите 1–2 секунды: чанки генерируются в фоне по 2 за кадр |
